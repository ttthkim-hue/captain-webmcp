# Captain V1 demo narration

Target: 1 minute 55 seconds to 2 minutes 15 seconds

Voice direction: calm US English male synthetic voice, medium pace, factual,
not promotional.

## Scene 1 — The hidden handoff

Most AI-team dashboards hide the most important moment: who should do the work,
why that route is appropriate, and who remains accountable. Captain is a shared
WebMCP control room that makes those handoffs visible to both the person and the
agent.

## Scene 2 — One mission, four roles

This public demo uses a synthetic software-release mission. Sol owns
architecture and final judgment. Luna handles scoped implementation. Qwen is a
bounded mechanical utility. Exact tools provide hashes, schemas, and
reproducible evidence. The person can inspect every task, risk, acceptance rule,
and recommended route.

## Scene 3 — Semantic tools instead of screen guessing

The page registers five structured tools through WebMCP. The agent can read the
mission, inspect one item, compare all worker routes, focus the same item in the
visible interface, and stage a reversible proposal. Inputs use exact task and
worker identifiers, so the agent does not need to scrape the page or guess at a
click path.

## Scene 4 — The agent changes shared state

Here, the agent inspects task T one zero two. It sees a medium-risk dashboard
implementation with explicit component and keyboard checks. The route comparison
selects Luna, focuses the task in the shared view, and stages the assignment.
The page updates immediately, so the person can see exactly what the agent did
and why.

## Scene 5 — The boundary remains human

Captain deliberately exposes no tool for approval, execution, publication, or
release. The staged proposal changes page state only. A person can return it or
approve it through the visible interface. The activity trace records that the
decision came from the human, while private data and external services remain
outside this demonstration.

## Scene 6 — What this demonstrates

Captain is a bounded interaction pattern, not a claim that real workers completed
a release. It demonstrates semantic site tools, shared human-agent state,
least-authority actions, and an explicit acceptance boundary. The next step is
to connect this pattern to a complete evidence packet, while preserving the
same human control.
