# Captain V2 evidence-packet narration

Measured runtime: 161.572 seconds including intro and outro.

Voice direction: calm US English male synthetic voice, normal pace, factual,
not promotional. `scripts/video-scenes.json` is the machine-readable source of
truth.

## Scene 1 — The hidden handoff

Most AI team dashboards hide the most important moment: who should do the work,
why that route is appropriate, and who remains accountable. Captain is an open
source WebMCP control room that makes the handoff visible to both the person and
the browser agent.

## Scene 2 — One mission, four roles

This demo uses public synthetic software release data. Sol owns architecture
and final judgment. Luna handles scoped implementation. Qwen is a bounded
mechanical utility. Exact tools provide schemas, tests, and hashes. The person
can inspect every task, risk, acceptance rule, and recommended route.

## Scene 3 — Semantic site tools

The page registers seven structured tools through WebMCP. The agent reads the
mission, inspects task T-102, compares all worker routes, focuses the same item
in the visible interface, and stages Luna as a reversible proposal. Exact
identifiers replace screen scraping and guessed click paths.

## Scene 4 — Shared agent state

The visible page and the agent tools use the same state and routing logic. The
comparison explains why Luna fits this medium-risk implementation while the
other roles do not. The agent can stage the recommendation, but only the
visible **Human approve route** control can authorize the handoff.

## Scene 5 — Routing becomes proof

After the person approves the route, Captain creates packet
`PKT-T-102-LUNA`. The packet binds the original task, chosen worker, evidence
method, acceptance criteria, public-synthetic classification, and false release
state into one stable handoff contract.

## Scene 6 — Deterministic receipt

The last two WebMCP tools let the agent inspect and verify the packet.
Verification recomputes the canonical JSON SHA-256 digest and records a passing
receipt. It still cannot approve or download. The human reviews the receipt,
approves the packet, and explicitly downloads the evidence envelope.

## Scene 7 — Human authority

The activity trace preserves who did what. Agent actions inspect, focus, stage,
and verify. Human actions approve the route, approve the packet, and download
it. The final record says no release was executed, and the downloaded digest
matches the packet shown on screen.

## Scene 8 — Why WebMCP

Captain demonstrates a bounded interaction pattern, not a claim that real
workers completed a release. Seven narrow site-owned tools, shared state,
deterministic proof, and explicit human gates make the workflow inspectable.
The working app, tests, and source are ready for the public challenge
submission.
